# Базовая спецификация

## Назначение

Это CMS-блог на Astro и EmDash. Публичная часть предназначена для чтения статей, поиска и навигации по рубрикам и тегам; редакторская — для управления этим контентом через EmDash Admin UI. Проект сохраняет один JavaScript/TypeScript-стек: отдельный WordPress-бэкенд не используется.

MVP — среда для проверки связки Astro + EmDash локально. Следующий этап — оценить два варианта публикации на Bunny.net: полностью статический сайт через Storage/Pull Zone или SSR-приложение в Magic Containers.

## Границы MVP

Входит:

- блог, страницы, категории, теги, полнотекстовый поиск и RSS;
- админ-интерфейс EmDash и аудит изменений;
- редактирование контента без обязательной пересборки работающего SSR-сайта;
- SQLite и локальное файловое хранилище для локальной разработки.

Не входит:

- production-инфраструктура, CI/CD и резервное копирование;
- отказоустойчивое многорепличное хранилище;
- e-commerce, сложные роли, локализация и не проверенные на прототипе плагины;
- включение комментариев без отдельного процесса модерации.

## Архитектура

```text
Редактор
  │
  └─ EmDash Admin UI (/_emdash/admin)
       │
       ├─ SQLite: data.db
       └─ локальные медиа: uploads/
              │
              ▼
        EmDash Live Collections
              │
              ▼
       Astro SSR + @astrojs/node
              │
              ▼
        публичный сайт и RSS
```

`astro.config.mjs` задаёт `output: "server"` и адаптер `@astrojs/node` в режиме `standalone`. Поэтому текущая версия — серверное Node-приложение: публичные страницы, API EmDash и административный интерфейс обслуживает один процесс. `@emdash-cms/plugin-audit-log` подключён для аудита действий в CMS.

SQLite хранится в `data.db`, а загруженные медиа — в `uploads/`. База игнорируется Git; медиа, добавленные редактором локально, следует рассматривать как рабочие данные, а не как механизм доставки в production.

## Модель контента

Источник начальной схемы и демонстрационных данных — `seed/seed.json`.

| Сущность | Назначение |
| --- | --- |
| `posts` | Статьи: заголовок, обложка, Portable Text, анонс; поддерживаются черновики, ревизии, поиск и SEO. |
| `pages` | Самостоятельные страницы, например «О проекте»: заголовок и Portable Text. |
| `category` | Иерархические рубрики постов. |
| `tag` | Неиерархические теги постов. |
| `primary` menu | Основная навигация сайта. |
| `sidebar`, `footer` | Области виджетов для страницы статьи и подвала. |

Идентификатор записи (`entry.id`) — её slug и используется в URL. Внутренний ULID — `entry.data.id`; он нужен для вызовов API, например при работе с таксономиями. Имена таксономий в запросах должны в точности совпадать со схемой: `category` и `tag`.

## Публичные маршруты

| Маршрут | Содержимое |
| --- | --- |
| `/` | Избранная и последние публикации. |
| `/posts` | Архив постов. |
| `/posts/[slug]` | Статья с авторством, метаданными и оглавлением. |
| `/pages/[slug]` | CMS-страница. |
| `/category/[slug]` | Посты рубрики. |
| `/tag/[slug]` | Посты тега. |
| `/search` | Полнотекстовый поиск. |
| `/rss.xml` | RSS-лента. |
| `/_emdash/admin` | Административный интерфейс; не публичный контентный маршрут. |

Страницы с данными CMS рендерятся на сервере. При запросах к EmDash следует передавать полученный `cacheHint` в `Astro.cache.set(cacheHint)`. Для изображений из полей CMS используется компонент `Image` из `emdash/ui`, поскольку поле изображения — объект `{ src, alt }`, а не строка.

## Развитие и публикация

Текущая реализация ориентирована на SSR. Для будущего теста Bunny.net возможны два независимых режима:

1. SSG: собрать `dist/` и разместить на Bunny Storage/Pull Zone. Обновление CMS в таком режиме требует новой сборки и деплоя; админка там не работает.
2. SSR: запустить Node standalone в Bunny Magic Containers. Для SQLite и медиа необходим persistent volume; при росте нагрузки SQLite следует заменить внешней БД, а локальное хранилище — объектным.

Детали окружения разработчика — в [local-env.md](local-env.md). Исходная гипотеза и план проверки Bunny — в корневом [RFC](../../RFC.md).
