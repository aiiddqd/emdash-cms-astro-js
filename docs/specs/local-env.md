# Локальная среда разработки

## Что требуется

- Node.js 22.12 или новее;
- npm 10 или новее;
- доступный порт `4321`.

В репозитории зафиксирован `package-lock.json`, поэтому для установки используем npm. Не запускайте `pnpm install`: это создаст другой lockfile, а в текущем окружении pnpm дополнительно может подобрать внешний workspace.

## Первый запуск

```bash
npm ci
make dev
```

`npm ci` устанавливает версии строго из `package-lock.json`. Команда `make dev` запускает `npm run dev`; её также можно выполнить напрямую.

После запуска доступны:

- сайт: <http://localhost:4321>;
- административная часть EmDash: <http://localhost:4321/_emdash/admin>.

Конфигурация EmDash читает стартовую схему и demo-контент из `seed/seed.json`. При первом запуске откройте админку и завершите первичную настройку: она применит seed к локальной базе. После этого сервер использует `data.db`, а медиа, загружаемые через админку, сохраняются в `uploads/`.

## Ежедневная работа

| Задача | Команда |
| --- | --- |
| Показать все команды | `make help` |
| Запустить dev-сервер | `make dev` |
| Проверить типы Astro | `make typecheck` |
| Собрать production-версию | `make build` |
| Запустить собранную версию | `make start` |
| Локально просмотреть сборку Astro | `make preview` |
| Обновить типы EmDash | `make types` |
| Проверить типы и сборку | `make verify` |

`make types` запускает `npx emdash types` и требует работающий локальный сервер. При изменении `seed/seed.json` или типов CMS перезапустите `make dev`; сгенерированный файл `emdash-env.d.ts` обновится и его следует проверить перед коммитом.

## Проверка перед передачей изменений

```bash
make verify
```

Команда последовательно выполняет `npm run typecheck` и `npm run build`. Для ручной проверки откройте главную, один пост, поиск и `/_emdash/admin`; создайте или отредактируйте тестовый материал и убедитесь, что результат виден на публичной странице.

## Локальные данные

- `data.db` и её служебные файлы (`data.db-*`) не попадают в Git.
- Файл `uploads/` содержит локальные медиа и стартовые изображения шаблона. Не удаляйте каталог целиком для сброса базы.
- Чтобы начать с чистой базы, сначала остановите сервер, сохраните нужные данные и удалите только `data.db` и связанные с ним `data.db-*`. Затем откройте админку и снова завершите первичную настройку, чтобы применить seed.

Сброс базы необратим для контента, созданного через админку. Для переноса данных между окружениями нужен отдельный процесс экспорта и резервного копирования; он не входит в MVP.

## Production-проверка локально

```bash
make build
make start
```

`make start` запускает standalone-entrypoint `dist/server/entry.mjs`. По умолчанию приложение слушает адрес и порт, заданные Node/Astro; при необходимости перед запуском задайте переменные окружения, например `HOST=0.0.0.0 PORT=4321 make start`.

Не запускайте одновременно `make dev`, `make preview` и `make start` на одном порту.
